Capitolul 6

Moștenire și polimorfism

Extinderea claselor, suprascrierea metodelor și interfețe

Conceptul de moștenire

Moștenirea este un mecanism fundamental în POO care permite unei clase (derivate) să preia membrii unei alte clase (de bază). Aceasta promovează reutilizarea codului și creează o relație ierarhică de tip „este-un" (is-a).

// Clasa de bază (părinte)
class Animal {
  public string Nume { get; set; }

  public void Mananca() {
    Console.WriteLine($"{Nume} mananca.");
  }
}

// Clasa derivată (copil)
class Caine : Animal {
  public void Latra() {
    Console.WriteLine($"{Nume} latra: Ham ham!");
  }
}

// Utilizare
Caine caine = new Caine();
caine.Nume = "Rex";
caine.Mananca(); // Metodă moștenită din Animal
caine.Latra();  // Metodă specifică clasei Caine
  • Sintaxa: class ClasaDerivata : ClasaDeBaza – operatorul : indică moștenirea.
  • C# permite moștenire simplă: o clasă poate moșteni direct doar o singură clasă de bază.
  • Clasa derivată are acces la toți membrii public și protected ai clasei de bază.
  • Constructorii nu se moștenesc, dar constructorul clasei de bază este apelat automat înaintea celui derivat.

Constructorii în moștenire și base

Cuvântul cheie base este folosit pentru a accesa membrii clasei de bază din clasa derivată. Este esențial în apelarea constructorilor clasei părinte și în accesarea metodelor suprascrise.

class Vehicul {
  public string Marca { get; set; }

  public Vehicul(string marca) {
    Marca = marca;
  }
}

class Masina : Vehicul {
  public int NumarUsi { get; set; }

  // Apelarea constructorului din clasa de bază cu base
  public Masina(string marca, int numarUsi) : base(marca) {
    NumarUsi = numarUsi;
  }
}

// base se poate folosi și pentru a apela metode din clasa părinte
class VehiculElectric : Vehicul {
  public override string ToString() {
    return $"Vehicul electric: {base.Marca}";
  }
}
  • base() este folosit în constructorul clasei derivate pentru a apela constructorul clasei de bază.
  • Apelul cu base trebuie să fie prima instrucțiune din constructorul derivatei.
  • base.Membru permite accesarea unui membru al clasei de bază care a fost ascuns sau suprascris.
  • Dacă nu specifici explicit base(), compilatorul apelează automat constructorul implicit al clasei de bază.

Metode virtuale și override

virtual permite unei metode din clasa de bază să fie suprascrisă în clasele derivate. override este folosit în clasa derivată pentru a oferi o implementare specifică a metodei virtuale.

class Forma {
  // Metodă virtuală – poate fi suprascrisă
  public virtual void Deseneaza() {
    Console.WriteLine("Desenez o forma generica.");
  }
}

class Cerc : Forma {
  // Suprascrierea metodei virtuale
  public override void Deseneaza() {
    Console.WriteLine("Desenez un cerc.");
  }
}

class Patrat : Forma {
  public override void Deseneaza() {
    Console.WriteLine("Desenez un patrat.");
  }
}
  • virtual marchează o metodă care poate fi suprascrisă; metodele sunt non-virtuale în mod implicit.
  • override este obligatoriu pentru a suprascrie o metodă virtuală; compilatorul verifică să existe o metodă virtuală corespunzătoare.
  • new ascunde metoda din clasa de bază fără a o suprascrie (nu participă la polimorfism).
  • sealed override blochează posibilitatea de a mai suprascrie metoda în clasele care derivă mai departe.

Polimorfismul

Polimorfismul (din greacă: „mai multe forme") permite tratarea obiectelor de tipuri diferite printr-o interfață comună. La runtime, metoda corectă este apelată în funcție de tipul real al obiectului, nu de tipul referinței.

// Colectie eterogenă tratată uniform
Forma[] forme = new Forma[] {
  new Cerc(),
  new Patrat(),
  new Cerc()
};

// Polimorfism: metoda corectă e apelată automat
foreach (Forma forma in forme) {
  forma.Deseneaza(); // Fiecare obiect își desenează propria formă
}

// Referința de tipul de bază poate stoca orice obiect derivat
Forma f = new Cerc();
f.Deseneaza(); // "Desenez un cerc." – legare dinamică
  • Legare dinamică (dynamic binding): metoda apelată este determinată la runtime, nu la compilare.
  • Upcasting: conversia implicită de la un tip derivat la tipul de bază (Forma f = new Cerc();).
  • Downcasting: conversia explicită de la tipul de bază la un tip derivat (Cerc c = (Cerc)f;).
  • is și as: operatori pentru verificarea tipului la runtime înainte de downcasting.

Clase abstracte

O clasă abstractă este o clasă care nu poate fi instanțiată direct. Este marcată cu cuvântul cheie abstract și servește ca șablon pentru clasele derivate. Poate conține atât metode abstracte (fără implementare), cât și metode concrete.

// Clasă abstractă – nu poate fi instanțiată
abstract class Angajat {
  public string Nume { get; set; }

  // Metodă abstractă – fără implementare
  public abstract decimal CalculeazaSalariu();

  // Metodă concretă – are implementare
  public void AfiseazaInfo() {
    Console.WriteLine($"Angajat: {Nume}, Salariu: {CalculeazaSalariu()}");
  }
}

class AngajatFullTime : Angajat {
  public override decimal CalculeazaSalariu() {
    return 5000m;
  }
}
  • O clasă abstractă nu poate fi instanțiată cu new; trebuie moștenită.
  • Metodele abstracte nu au corp și forțează clasele derivate să le implementeze.
  • O clasă concretă care moștenește o clasă abstractă trebuie să implementeze toate metodele abstracte.
  • Diferența față de interfețe: clasele abstracte pot avea câmpuri, constructori și metode cu implementare.

Interfețe

O interfață definește un contract pe care clasele care o implementează trebuie să îl respecte. Conține doar semnături de metode, proprietăți, evenimente și indexatori, fără implementare. O clasă poate implementa mai multe interfețe.

// Definirea unei interfețe
interface IVolabil {
  void Zboara();
  int AltitudineMaxima { get; }
}

interface IAcvatic {
  void Inoata();
}

// O clasă poate implementa mai multe interfețe
class Rata : IVolabil, IAcvatic {
  public int AltitudineMaxima => 1000;

  public void Zboara() {
    Console.WriteLine("Rata zboara.");
  }

  public void Inoata() {
    Console.WriteLine("Rata inoata.");
  }
}
  • Interfețele se declară cu interface și, prin convenție, numele lor începe cu I.
  • Toți membrii unei interfețe sunt implicit public și nu pot avea modificatori de acces.
  • O clasă poate implementa mai multe interfețe, rezolvând limitarea moștenirii simple.
  • Implementare explicită: când două interfețe au membri cu același nume, se folosește NumeInterfata.Metoda().
